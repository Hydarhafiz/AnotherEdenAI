**Progress partial (replace src/web/templates/partials/progress.html):**

The progress partial must:
1. Set `sse-connect="/api/stream/{{ job_id }}"` — HTMX opens SSE GET connection automatically
2. Use `sse-swap="node_status"` — swaps the progress-status div content when node_status events arrive
3. Include inline JavaScript that parses the SSE event JSON and renders human-readable text
4. Show "Validating... attempt 2/3" when node=VALIDATE and attempt > 1 (per D-13)
5. Use `sse-close="done"` — closes the connection when done event arrives

Key HTMX SSE behaviour: `sse-swap="node_status"` swaps the *raw data string* from the SSE event into the element's innerHTML. Since the data is JSON, we need a small inline script to intercept the `htmx:sseMessage` event and transform the JSON into readable text before it lands in the div.

```html
<!-- partials/progress.html — returned by POST /api/query -->
<!-- HTMX opens SSE GET connection to /api/stream/{job_id} automatically. -->
<!-- sse-close="done" tells the SSE extension to close when "done" event fires. -->
<div id="progress-container"
     hx-ext="sse"
     sse-connect="/api/stream/{{ job_id }}"
     sse-close="done">

  <p><strong>Running pipeline...</strong></p>

  <!-- sse-swap="node_status" swaps this div's innerHTML on every node_status event. -->
  <!-- The inline script intercepts htmx:sseMessage to format JSON as readable text. -->
  <div id="progress-status" sse-swap="node_status" aria-live="polite">
    Starting...
  </div>

  <!-- sse-swap="result" replaces result-area when final result event arrives. -->
  <div id="result-area"
       sse-swap="result"
       hx-swap="outerHTML"
       hx-target="#result-container">
  </div>
</div>

<script>
/**
 * Transform SSE node_status JSON events into readable progress text (D-13).
 * HTMX normally swaps raw SSE data into the target element.
 * We intercept htmx:sseMessage to parse JSON and render human-readable text.
 */
(function () {
  const NODE_DESCRIPTIONS = {
    "PLAN":     "Planning query strategy...",
    "CYPHER":   "Generating Cypher query...",
    "VALIDATE": "Validating query results...",
    "ANALYZE":  "Analyzing team composition...",
    "FORMAT":   "Formatting recommendations...",
    "ERROR":    "Pipeline error — please retry.",
  };

  document.addEventListener("htmx:sseMessage", function (evt) {
    // Only handle node_status events (ignore result and done)
    if (evt.detail.type !== "node_status") return;

    let payload;
    try {
      payload = JSON.parse(evt.detail.data);
    } catch (e) {
      return;  // Non-JSON data — let HTMX handle it normally
    }

    if (payload.event !== "node_status") return;

    const node = payload.node || "UNKNOWN";
    const attempt = payload.attempt || 1;
    const max = payload.max || 1;

    let text = NODE_DESCRIPTIONS[node] || (node + "...");

    // D-13: "Validating... attempt 2/3" for VALIDATE retries
    if (node === "VALIDATE" && attempt > 1) {
      text = "Validating... attempt " + attempt + "/" + max;
    }

    // Update the progress-status div content directly
    const statusDiv = document.getElementById("progress-status");
    if (statusDiv) {
      statusDiv.textContent = text;
    }

    // Prevent HTMX from swapping raw JSON into the div
    evt.preventDefault();
  });
})();
</script>
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SSE event data → Jinja2 template | LLM-generated team names and synergy text rendered into HTML |
| HTMX sse-swap innerHTML | SSE data (JSON) becomes innerHTML via htmx:sseMessage intercept |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-11 | Tampering | Jinja2 template XSS via LLM output in result card | mitigate | Jinja2 HTML autoescaping is enabled by default for .html templates — character names and synergy text are HTML-escaped; `{{ result.error }}` output is escaped |
| T-04-12 | Tampering | htmx:sseMessage JSON parse from SSE data | accept | JSON.parse() on SSE node_status data; payload is server-generated (not user input); node names come from NODE_LABELS map (fixed set); no eval() or innerHTML assignment of parsed values |
| T-04-13 | DoS | Browser loading 400+ chars + 489 Grastas in DOM | accept | ~900 DOM nodes for checklist; client-side filter does not re-query server; modern browsers handle 1000+ list items without issue; Phase 4 single-user scope |
</threat_model>
