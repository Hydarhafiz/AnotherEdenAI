# Phase 03.1: Code Review Report

**Reviewed:** 2026-04-19T00:00:00Z
**Depth:** standard
**Files Reviewed:** 5
**Status:** issues_found

## Summary

Reviewed the nodriver-based ETL scraper implementation for phase 03.1. The code is generally well-structured with clear docstrings, correct column-mapping logic, and solid Pydantic v2 validation patterns. The main concerns are: a hardcoded developer-specific filesystem path that will silently fail on any other machine (critical portability/reliability issue), a missing `await` before `browser.stop()` that may leave the browser process dangling, and a 2-second unconditional sleep that is fragile under network latency. The test file duplicates the same hardcoded path. The `httpx` dependency declared in `pyproject.toml` appears to be a leftover from the prior implementation.

## Critical Issues

### CR-01: Hardcoded developer-specific Chromium path will silently fail on any other machine

**File:** `src/etl/scraper.py:39`
**Issue:** `CHROMIUM_PATH` is hardcoded to `/home/shogunix/.cache/ms-playwright/chromium-1187/chrome-linux/chrome`. This path does not exist on CI, any other developer machine, or a Docker container. `uc.start()` at line 182 will raise a `FileNotFoundError` (or silently launch the wrong Chrome) without any contextual error message, making the failure opaque to the caller. The path also embeds a specific Playwright build number (`chromium-1187`) that will become stale after a Playwright upgrade.

**Fix:** Read the path from an environment variable with a documented fallback, and validate existence at startup:
```python
import os, shutil

_DEFAULT_CHROMIUM = "/home/shogunix/.cache/ms-playwright/chromium-1187/chrome-linux/chrome"
CHROMIUM_PATH: str = os.getenv("CHROMIUM_PATH", _DEFAULT_CHROMIUM)

# Validate once at import time so failures are loud and actionable.
if not os.path.isfile(CHROMIUM_PATH):
    raise EnvironmentError(
        f"Chromium binary not found at {CHROMIUM_PATH!r}. "
        "Set the CHROMIUM_PATH environment variable or run "
        "'playwright install chromium'."
    )
```

## Warnings

### WR-01: `browser.stop()` likely requires `await` — browser process may not be cleaned up

**File:** `src/etl/scraper.py:197`
**Issue:** `browser.stop()` is called without `await` inside the `finally` block. In nodriver, `Browser.stop()` is an async coroutine. Calling it without `await` returns a coroutine object that is immediately garbage-collected, meaning the underlying Chrome process is never actually sent a shutdown signal. This leaves a zombie Chrome process after every `scrape_all()` call.

**Fix:**
```python
finally:
    await browser.stop()
```

Verify against the installed nodriver version with `import inspect; inspect.iscoroutinefunction(browser.stop)`.

### WR-02: Unconditional 2-second sleep is fragile — may be too short or wasteful

**File:** `src/etl/scraper.py:57`
**Issue:** `await tab.sleep(2)` waits a flat 2 seconds for the Cloudflare JS challenge to resolve. On a slow network this may not be enough, causing the Turnstile check at line 61 to raise a `RuntimeError` even though the page would have loaded with slightly more time. Conversely, on a fast local connection every page fetch wastes 2 seconds unnecessarily (7 pages = 14 seconds of pure sleep per `scrape_all()` call).

**Fix:** Poll for readiness or use a configurable timeout. A simple approach using nodriver's wait API:
```python
# Wait up to 10 s for the real page title to appear, check every 0.5 s.
WAIT_TIMEOUT_S: float = float(os.getenv("CF_WAIT_TIMEOUT", "10"))

async def fetch_page(browser, url: str) -> BeautifulSoup:
    tab = await browser.get(url)
    for _ in range(int(WAIT_TIMEOUT_S / 0.5)):
        await tab.sleep(0.5)
        html = await tab.get_content()
        soup = BeautifulSoup(html, "html.parser")
        title = soup.find("title")
        if title is None or "Just a Moment" not in title.get_text():
            return soup
    raise RuntimeError(
        f"Cloudflare Turnstile blocked {url!r} after {WAIT_TIMEOUT_S}s. "
        "Install opencv-python and add 'await tab.verify_cf()' to fetch_page()."
    )
```

### WR-03: Default Neo4j password hardcoded in constants — will be committed to version control

**File:** `src/etl/constants.py:9`
**Issue:** `NEO4J_AUTH` falls back to `"neo4j/anothereden"` when the environment variable is absent. Although this file is not in the explicit review scope, `models.py` imports from it, and this pattern will be replicated if `constants.py` is used as a template. The hardcoded credential means that any developer who forgets to set `NEO4J_AUTH` will silently authenticate with the default password — a security risk if the database is ever network-accessible.

**Fix:** Remove the fallback value and raise explicitly when the variable is absent:
```python
_raw_auth = os.getenv("NEO4J_AUTH")
if not _raw_auth:
    raise EnvironmentError("NEO4J_AUTH environment variable is required (format: user/password)")
NEO4J_AUTH = tuple(_raw_auth.split("/", 1))
```

## Info

### IN-01: `httpx` retained as a direct dependency after migration to nodriver

**File:** `pyproject.toml:11`
**Issue:** `httpx>=0.27` is still listed in `[project.dependencies]`. The module-level docstring in `scraper.py` (line 70) explicitly notes that parse functions are "UNCHANGED from original httpx implementation", confirming the scraper no longer uses httpx directly. Leaving it as a hard dependency adds unnecessary install weight and will confuse future contributors.

**Fix:** Move `httpx` to `[project.optional-dependencies]` or remove it if no other module imports it:
```toml
[project.optional-dependencies]
dev = [
    "httpx>=0.27",   # retained for ad-hoc HTTP debugging; not used by scraper
    ...
]
```
