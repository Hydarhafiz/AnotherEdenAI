## Summary

The current scraper (`src/etl/scraper.py`) uses `httpx.AsyncClient` to fetch wiki pages, which returns 403/429 errors because `anothereden.wiki` is behind Cloudflare Turnstile. The fix is surgical: replace only `fetch_page()` with a nodriver-based implementation. All parse functions, Pydantic models, and the Neo4j loader remain completely untouched.

nodriver 0.48.1 is a pure-async Python library that drives Chrome via the Chrome DevTools Protocol (CDP) without webdriver injection, making it undetectable to Cloudflare's JS fingerprinting. It exposes `await browser.get(url)` which returns a Tab, and `await tab.get_content()` which returns the full page HTML as a string — a drop-in for `response.text`. The BeautifulSoup wrapping in `fetch_page()` remains unchanged.

**The critical environment constraint is Chrome.** There is no Linux-native Chrome in PATH, but two viable paths exist: (1) Playwright's bundled Chromium at `~/.cache/ms-playwright/chromium-1187/chrome-linux/chrome` (version 140, verified executable), or (2) the Windows Chrome at `/mnt/c/Program Files/Google/Chrome/Application/chrome.exe` (confirmed present, but WSL2 → Windows subprocess communication is unreliable for CDP). The plan must use the Playwright Chromium path with `browser_executable_path`.

**Primary recommendation:** Replace `fetch_page()` with a nodriver sequential implementation (one browser, one tab at a time). Do NOT parallelize with asyncio.gather — nodriver's browser is not designed for concurrent tab operations across multiple await chains. Serialize the 7 fetches: open browser, iterate URLs sequentially, close browser.

### Pattern 2: fetch_page() Signature Preservation

The existing callers of `fetch_page(client, url)` are only inside `scrape_all()`. The signature of `fetch_page` can change to `fetch_page(browser, url)` replacing the `httpx.AsyncClient` parameter with the nodriver Browser — callers are internal only and are updated together. Alternatively, scrape_all() can inline the navigation and drop fetch_page() entirely since it was only a thin wrapper. The simpler path is to inline in scrape_all() and remove fetch_page() — fewer moving parts.

**Recommended:** Remove the `fetch_page(client, url)` function; inline the nodriver calls directly in `scrape_all()`. The success criterion says "fetch_page() uses nodriver" so if the requirement expects the function to exist, keep it as `fetch_page(browser, url) -> BeautifulSoup`.

### Pattern 3: Manual Overrides in parse_character()

**What:** After `CharacterRow.model_validate(raw)`, apply a hardcoded override dict keyed by exact character name.

**When to use:** Characters where the wiki data is wrong or missing (Anabel ES = Spear, Mazrika = Axe).

**Example:**

### Anti-Patterns to Avoid

- **asyncio.gather() with multiple browser.get() calls:** nodriver's Browser is not thread-safe for concurrent tab navigation. Sequential iteration is the correct pattern.
- **headless=True without display fallback:** nodriver's headless mode has known stability issues; if the environment has no display, use `DISPLAY=:99` with Xvfb, or use the `--headless=new` Chrome flag via `browser_args`.
- **Keeping httpx dependency for scraping:** Remove `import httpx` and related constants (`SEMAPHORE`, `LIMITS`, `HEADERS`, `TIMEOUT`) from scraper.py — they are dead code after the replacement.
- **Using `asyncio.run()` to start nodriver:** nodriver has its own event loop (`uc.loop()`). When called inside an already-running loop (e.g., pytest-asyncio), use `await uc.start(...)` directly — do not wrap in `asyncio.run()`. Since the project uses `asyncio_mode = auto` in pytest.ini, `await uc.start()` works correctly in async test functions.
- **Opening 7 separate browser instances:** Each `uc.start()` launches a full Chrome process (~150-200MB RAM). One browser, sequential navigation is correct.

| Problem | Don't Build | Use Instead | Why |

## Common Pitfalls

### Pitfall 1: headless=True Instability
**What goes wrong:** Passing `headless=True` to `uc.start()` can cause recursion errors or silent failures in some nodriver versions.
**Why it happens:** headless mode exposes different CDP behavior; anti-detection patches in nodriver interact with headless flags.
**How to avoid:** Default to `headless=False`. In the WSL2 environment, the DISPLAY variable is already set to `:0` (verified), so non-headless Chrome can run. If a CI/server context with no display is needed later, add `--headless=new` via `browser_args` instead of the `headless=True` parameter.
**Warning signs:** Chrome launches but `get_content()` returns an incomplete page, or process crashes without a Python traceback.

### Pitfall 2: Windows Chrome vs Linux Chromium Path
**What goes wrong:** nodriver may auto-detect `/mnt/c/Program Files/Google/Chrome/Application/chrome.exe` on WSL2, which opens a Windows window and can't communicate back to the WSL2 process via CDP.
**Why it happens:** WSL2 path detection looks at the whole filesystem; Windows executables appear valid but run in a different process namespace.
**How to avoid:** Always pass `browser_executable_path` explicitly pointing to the Linux Chromium binary.
**Known good path:** `/home/shogunix/.cache/ms-playwright/chromium-1187/chrome-linux/chrome` (version 140, verified runnable)
**Warning signs:** Chrome window opens on Windows desktop; Python hangs waiting for CDP connection.

### Pitfall 3: Cloudflare Still Blocking After Browser Navigation
**What goes wrong:** Even with nodriver, some Cloudflare configurations require an interactive checkbox click (Turnstile "managed" mode).
**Why it happens:** anothereden.wiki may present a "I'm not a robot" Turnstile challenge before showing content.
**How to avoid:** After `browser.get(url)`, call `await tab.sleep(2)` to let the JS challenge auto-resolve. If the page HTML still contains Cloudflare challenge markers (e.g., `<title>Just a Moment</title>`), call `await tab.verify_cf()` (requires `opencv-python`). The wiki may not trigger Turnstile at all since it is a MediaWiki — verify on first run.
**Warning signs:** `tab.get_content()` returns HTML with title "Just a Moment" or "Checking your browser".

### Pitfall 4: Semaphore / asyncio.gather Removal
**What goes wrong:** The old `SEMAPHORE = asyncio.Semaphore(5)` and `asyncio.gather(...)` pattern from the httpx version is removed but accidentally left as dead code or incorrectly ported.
**Why it happens:** Copy-paste from old scrape_all() structure.
**How to avoid:** Completely delete `SEMAPHORE`, `LIMITS`, `HEADERS`, `TIMEOUT` constants and the `import httpx` line. Replace `asyncio.gather(fetch_page(...) for ...)` with a sequential `for` loop.

### Pitfall 5: parse_character Override Placement
**What goes wrong:** Overrides applied BEFORE `model_validate()` — the raw dict is mutated, not the validated model.
**Why it happens:** Overriding `raw["weapon"]` before validation works but is fragile (raw dict might use different casing or field names).
**How to avoid:** Apply overrides AFTER successful validation using `char.model_copy(update={"weapon": ...})`. This preserves all other validated fields and uses the Pydantic-normalized field name.

### Pitfall 6: pytest-asyncio Loop Conflict with nodriver
**What goes wrong:** `uc.loop().run_until_complete(main())` called inside a pytest-asyncio test function causes "This event loop is already running" error.
**Why it happens:** pytest-asyncio with `asyncio_mode = auto` already manages the event loop; nodriver's `uc.loop()` tries to create/run its own loop.
**How to avoid:** In test context, use `await uc.start(...)` directly — never call `uc.loop().run_until_complete()`. Tests for the scraper should be integration-only (marked `@pytest.mark.integration`), not unit tests, because a real Chrome process is required.
