# Another Eden AI — GraphRAG Team Builder

## Project Overview

An agentic AI system that solves the "Mule Problem" in Another Eden RPG: optimizing allocation of limited shared resources (Grastas, personality traits) across a party to maximize team effectiveness.

The system uses a Knowledge Graph (Neo4j) to model character-trait-Grasta relationships, and a LangGraph multi-agent pipeline to generate and validate optimal team recommendations constrained to the player's actual owned roster.

**Core value:** Mathematically optimal team recommendations constrained to the player's actual roster, zero hallucinated mechanics.

## Architecture

```
Browser (HTMX + SSE)
        |
        v
FastAPI Web Layer (src/web/)
  POST /api/query  ->  SSE stream of pipeline events + final HTML fragment
  GET  /api/entities -> character + Grasta master list for roster checklist
  POST /admin/refresh-data -> triggers ETL (requires X-Admin-Key header)
        |
        v
LangGraph Pipeline (src/workflow/)
  PLAN -> GENERATE_CYPHER -> VALIDATE -> ANALYZE -> FORMAT
  (Sonnet 4.6 for reasoning nodes; Haiku 4.6 for validation)
        |
        v
Neo4j Graph Database
  Nodes: Character, Trait, Grasta, Ore
  Edges: HAS_TRAIT, REQUIRES_TRAIT
  Loaded by ETL pipeline (src/etl/)
```

**Tech stack:**
- Python 3.12, uv (package manager)
- FastAPI 0.136 + Jinja2 + SSE (web layer)
- LangGraph 1.0 + langchain-anthropic (agent pipeline)
- Neo4j 5.x / AuraDB Free (graph database)
- Pydantic v2 (schema validation at every boundary)
- pytest + pytest-asyncio (test suite)

## Setup

### 1. Install dependencies

```bash
uv sync
```

### 2. Configure environment variables

Copy `.env.example` to `.env` and fill in the required values:

| Variable | Required | Purpose |
|----------|----------|---------|
| `NEO4J_URI` | yes | Neo4j bolt URI. For local Docker: `bolt://localhost:7687`. For AuraDB Free: `neo4j+s://xxxxxxxx.databases.neo4j.io` |
| `NEO4J_AUTH` | yes | Neo4j credentials in `user/pass` format (e.g. `neo4j/yourpassword`). Avoid `/` in password for AuraDB. |
| `LLM_PROVIDER` | yes | One of `anthropic`, `openrouter`, `bedrock`, `ollama` |
| `ANTHROPIC_API_KEY` | conditional | Required when `LLM_PROVIDER=anthropic` |
| `OPENROUTER_API_KEY` | conditional | Required when `LLM_PROVIDER=openrouter` |
| `OLLAMA_MODEL` | no | Model name for `LLM_PROVIDER=ollama` (default: `llama3.2`) |
| `ETL_MODE` | no | `strict` (default) or `lenient` |
| `ADMIN_KEY` | yes | Secret for admin-only web routes; sent as `X-Admin-Key` header |

### 3. Set up Neo4j (AuraDB Free — recommended for cold clone)

AuraDB Free is Neo4j's free cloud tier. No local Docker required.

1. Create a free instance at [console.neo4j.io](https://console.neo4j.io)
2. Copy the connection URI (format: `neo4j+s://xxxxxxxx.databases.neo4j.io`)
3. Set in `.env`:
   ```
   NEO4J_URI=neo4j+s://xxxxxxxx.databases.neo4j.io
   NEO4J_AUTH=neo4j/<your-password>
   ```
   Note: avoid `/` in your AuraDB password (it is used as a delimiter in `NEO4J_AUTH`).
4. Run the ETL pipeline once to populate the graph:
   ```bash
   python -m src.etl.run_etl
   ```
   This scrapes the Another Eden wiki and loads Character, Grasta, Ore, and Trait nodes.
   Expected output: ~389 Characters, ~489 Grastas, ~61 Ores, ~126 Traits loaded.

**Local Neo4j (Docker alternative):**
```bash
docker compose up -d   # starts Neo4j 5 with APOC plugin
# then set NEO4J_URI=bolt://localhost:7687 and NEO4J_AUTH=neo4j/anothereden in .env
```

## Running Tests

```bash
# Unit tests only (no database required)
pytest -m 'not integration' --tb=short -q

# Full suite (requires NEO4J_URI + NEO4J_AUTH in .env and ETL data loaded)
pytest --tb=short

# Phase 5 integration tests specifically
pytest tests/integration/test_e2e_phase5.py -m integration -x -q
```

**What the test suite covers:**
- LangGraph node unit tests (PLAN, CYPHER, VALIDATE, ANALYZE, FORMAT) — no LLM or DB calls
- Graph routing tests (retry loop, retry cap exhaustion)
- ETL idempotency and schema assertion tests
- Integration tests: happy path team recommendation, name normalization, empty-result alternatives, retry cap exhaustion, admin endpoint authorization

## Running the Web App

```bash
uvicorn src.web.app:app --reload
```

Open [http://localhost:8000](http://localhost:8000). The UI provides:
- Roster checklist (Characters and Grastas tabs, synced to localStorage)
- Natural language query input
- Live pipeline progress via SSE (PLAN → CYPHER → VALIDATE → ANALYZE)
- Team recommendation rendered as a character card grid (4 frontline / 2 reserve)
- Top-3 alternative teams when no exact match is found

## Admin: Trigger ETL Refresh

```bash
curl -X POST http://localhost:8000/admin/refresh-data \
  -H "X-Admin-Key: <your ADMIN_KEY value>"
```

Returns `{"status": "ok", "message": "ETL complete: N chars, M Grastas loaded"}` on success.
